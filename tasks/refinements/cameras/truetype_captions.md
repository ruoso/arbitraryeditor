## What this task is

Camera captions on the contact sheet are drawn today by an in-tree `constexpr`
bitmap glyph table — 191 cells (ASCII + printable Latin-1), 1-bit glyphs scaled
by integer pixel replication, each set bit written as an opaque black shadow at
`(+scale,+scale)` then opaque white, unmapped code points collapsing to one
hollow fallback box per run (`src/commands/glyphs.cpp`,
`src/commands/contact_sheet.cpp:254-279`, A21 clause 3 + its `caption_latin1`
amendment). That table was `editor.cameras.contact_sheet`'s deliberate interim
(D-sheet-4): a real font is unreachable from a headless L1 job because ImGui's
atlas is L3-only, so a table was the one dependency-free, background-blind,
blend-free way to draw text in `commands`.

This leaf replaces the table with a **real bundled face**. It vendors
`third_party/stb/stb_truetype.h` beside the already-vendored
`stb_image_write.h`, bundles the static `Inter-Regular.ttf` (`glyf` outlines,
OFL 1.1) into the reserved `assets/fonts/` slot, and turns the `.ttf` into a
linked `const` byte array at **build time** (a CMake step) so it is embedded
exactly as the table was — no runtime file load, nothing for a headless job to
fail to find. `stb_truetype` rasterizes an 8-bit coverage bitmap, so `draw_text`
becomes an antialiased composite of coverage over the caption background in the
**linear** working space (libarbc's transfer functions, the same math `render`
uses), keeping the white-glyph + black-shadow legibility pair. `text_width` and
`fit_text` are driven by the face's advance metrics; `next_code_point` (the
UTF-8 decoder) survives unchanged. The 5×7 table, its Latin-1 extension, its
fallback box and `text_set_bits` are deleted — a real face covers Latin-1
natively and reports its own `.notdef` for the rest, so the missing-glyph box
becomes the font's business.

The observable change: accented and future non-Latin names caption in a real
proportional face; both contact-sheet goldens re-baseline for the new caption
shapes; the public drawing/measuring API keeps its signatures.

## Why it needs to be done

The predecessor named this debt while shipping the interim. D-sheet-4 recorded
the table as *"the defensible interim"* and surfaced *"whether the editor should
eventually ship a real bundled font"* to the parking lot
(`tasks/refinements/editor/contact_sheet.md:655-687,755-763`). The 2026-07-28
parking-lot triage **decided it** — adopt a bundled font, scheduled as this leaf
(`tasks/parking-lot.md:18-26`, closure record naming
`editor.cameras.truetype_captions`; the original item text is preserved at
`d0843c5^:tasks/parking-lot.md:228-232`) — and the face/licence/embed decisions
were taken with human sign-off and recorded in the `.tji` note (`:522`).

It is worth 2.5d because the table's charset is a wall the editor keeps building
higher by hand. `caption_latin1` already conceded that boxing a name the user
typed is a visible defect (`Café` → `Caf□`), and extended the table one range to
fix it — but `Łódź`, `Škoda`, Greek and Cyrillic names still box, and every
future range is another hand-drawn block of binary literals to author and
proofread. A real face ends that: it draws its native repertoire and reports
`.notdef` for the rest, so the editor stops legislating which of a user's names
are drawable — the same arbitrariness argument (`docs/00-design.md:13-26`,
`.tji:412` "no allowlists") that motivated `caption_latin1`, taken to its
structural conclusion. General i18n beyond the face's coverage remains open
(`docs/00-design.md:518`); this leaf does not close it, it removes the
hand-drawn ceiling under it.

## Constraints / requirements

1. **The public drawing/measuring API keeps its signatures.** `text_width(
   std::string_view, int)`, `fit_text(std::string_view, int, int)`,
   `draw_text(Srgb8Image&, int, int, std::string_view, int)` and
   `next_code_point(std::string_view, std::size_t&)` are unchanged. Retiring
   `text_cells`/`text_set_bits` must update **all** their callers (all in-tree —
   `commands`/`views`/tests, verified by grep) in the same change.
2. **The face is embedded, not loaded.** No runtime file I/O, no `assets/` path
   resolved at run time, no `FILE*`. The `.ttf` becomes a linked `const` byte
   array via a build step; the offline caption path performs zero filesystem
   access for the font, exactly as the `constexpr` table did.
3. **One external, one containment.** `stb_truetype.h` is instantiated in
   **exactly one** `commands` TU (`#define STB_TRUETYPE_IMPLEMENTATION`), reached
   through the PRIVATE `third_party` include dir; `scripts/check_levels.py` gains
   `EXTERNAL_ALLOWED["stb_truetype"] = {"commands"}` **and** the matching
   `EXTERNAL_RE` regex. No other component may include it. `stb_image_write`
   stays the sole **encode** dependency.
4. **Text composites in linear space; the tile image stays a copy.** Caption
   coverage is composited over the strip background using
   `arbc::srgb8_to_linear`/`linear_to_srgb8`, never an sRGB8 byte blend. The
   per-tile `std::copy` image composite (`contact_sheet.cpp:359-381`) and the
   background fill are **byte-unchanged** — the tile-rect byte-identity law
   (D-sheet-2) still holds for images.
5. **Keep the white-glyph + black-shadow pair.** `draw_text` still lays a black
   shadow at `(+scale,+scale)` then white text, each now an antialiased coverage
   composite, so captions stay legible on light/dark/mid-grey/transparent
   backgrounds.
6. **An unmapped code point still renders something.** A code point outside the
   face's coverage (and U+FFFD from malformed input) renders the face's own
   `.notdef` glyph (stb glyph index 0), not empty space — the bounded, visible
   degradation D-sheet-4 required, now the font's business.
7. **Captions stay inside their strip.** Glyphs and the shadow fall within the
   `caption_height = k_glyph_cell_height * caption_scale` strip the layout
   allocates below each tile; no ink spills into the tile image above or the
   gutter. Descenders and the shadow offset are accounted for in the baseline
   placement.
8. **Levelization unchanged beyond the one external.** `commands` stays L1;
   `ALLOWED["commands"]` is untouched; no ImGui/GL/SDL include; no new component,
   no new DAG edge. `src/base/**`, `src/render/**`, `src/gl/**`, `src/dock/**`,
   `src/views/**`, `src/app/**` are byte-unchanged.
9. **No new thread, no new shared state.** The caption composite runs inside
   `run_export`'s existing sheet phase on its existing thread; the A18 progress
   snapshot and cancel atomic are untouched.
10. **Determinism.** The rasterization is bit-reproducible across platforms and
    toolchains: `stb_truetype`'s integer rasterizer at a fixed pixel height and
    fixed sub-pixel policy, no `std::locale`, no `wchar_t`, no platform font, no
    time/rand. The two goldens are byte-exact with **no tolerance** — a
    rasterizer that is not deterministic fails the golden immediately.
11. **The licence text ships in-repo and is handed forward.** `OFL.txt` sits
    beside `assets/fonts/Inter-Regular.ttf`; the vendored set (Inter +
    `stb_truetype`) is recorded so `editor.packaging.package` carries the licence
    into the installed artifact.

     differs pairwise, and at least one interior pixel is an **intermediate**
     intensity (neither background nor full ink) — the antialiasing signal a
     1-bit table cannot produce. **Anti-vacuity:** an empty string draws nothing;
     `"A"` at scale 2 draws strictly more lit pixels than at scale 1.
  2. **An unmapped code point renders the face's `.notdef`, not nothing.**
     `TEST_CASE("contact_sheet: an uncovered code point renders .notdef ink")` —
     `draw_text` of `"中"` (U+4E2D, outside Inter's coverage) and of the U+FFFD

     **Anti-vacuity:** the same scratch image captioned `" "` (space) is blank at
     those columns, so the `.notdef` box is proven drawn, not assumed.
  3. **The UTF-8 decoder is unchanged (charset case survives the swap).** The
     shipped `TEST_CASE("contact_sheet: the UTF-8 decoder is total and always

     truncation case's `text_width(result) <= max_width` law now measures **stb
     advances**, but the property is identical.
  4. **`text_width`/`fit_text` track the face's metrics.**
     `TEST_CASE("contact_sheet: caption width and fit follow the font advances")`
     — `text_width` is monotone non-decreasing as characters are appended, is
     zero for the empty string, and scales with `scale`; `fit_text` never returns
     a caption whose `text_width(result, scale)` exceeds `max_width`, and
     **anti-vacuity:** a width in a `[0,200]` sweep both (a) truncates with a
     trailing ellipsis and (b) leaves a short name untruncated.
  5. **Text composites in linear space over the strip background.**
     `TEST_CASE("contact_sheet: captions composite coverage in linear space")` —
     `draw_text` of an accented name over a **mid-grey** background produces
     edge pixels whose values match a reference computed as
     `linear_to_srgb8(coverage·ink_linear + (1−coverage)·bg_linear)` for the
     stb coverage of at least one sampled edge pixel, and **not** the sRGB8-byte

     values at mid-grey — this is the case that fails a gamma-space
     implementation). Over a **transparent** background the result is
     premultiplied-linear `over` (partial alpha at edges), matching `render`'s
     `to_srgb8_over` convention. **The shadow+white pair holds:** the darkest
     pixels form a shadow offset by `(+scale,+scale)` from the lightest, on every
     tested background (Constraint 5).
  6. **Nothing outside the caption strip is touched.**
     `TEST_CASE("contact_sheet: captions stay within their strip")` — after
     `draw_text` at the strip origin for the widest test name at scale 1 and 2,
     every pixel above `caption_y` and outside `[caption_x, caption_x +
     text_width]` is byte-identical to the pre-draw image (Constraint 7),
     including the descender and shadow rows.

## Decisions

- **D-truetype_captions-1 — Bundle Inter Regular (static `glyf`, OFL 1.1);
  vendor `stb_truetype.h`; both confined to `commands`.**
  The face is the static `Inter-Regular.ttf` with TrueType `glyf` outlines,
  under the SIL Open Font Licence 1.1, dropped in `assets/fonts/`;
  `third_party/stb/stb_truetype.h` sits beside `stb_image_write.h`.
  *Rationale:* (i) **OFL 1.1 permits bundling/redistribution inside software**
  and Inter carries **no reserved font name** — load-bearing, because OFL's RFN
  clause forces a rename on any *modification* and subsetting the face is a
  modification, so an RFN face could not be vendored-and-subset without renaming.
  (ii) **Inter is designed for small-size legibility and to work unhinted**, the
  exact regime `stb_truetype` imposes (it ignores hinting), where a
  hinting-dependent face (DejaVu Sans) surrenders its advantage. (iii) **Static
  `glyf`, never variable/CFF** — Inter ships variable by default and
  `stb_truetype` supports neither variable axes nor CFF outlines well; the
  static `glyf` build is stb's best-tested path.
  *Alternative rejected (recorded, not deferred):* **DejaVu Sans** (Bitstream
  Vera + Arev, equally permissive, ubiquitous on the Linux v1 target) — a
  one-line change to the face choice if a more conservative face is ever wanted,
  but it leans on hinting stb discards. *Alternative rejected:* an RFN-bearing
  or variable/CFF face — either illegal to subset without renaming or unsupported
  by the rasterizer. **Doc delta: A27; one-clause amendment to A20 (second
  vendored header).**

- **D-truetype_captions-2 — Embed the `.ttf` as a build-generated linked byte
  array; never load it at runtime.**
  A CMake step turns `assets/fonts/Inter-Regular.ttf` into a generated
  `.cpp` under the build dir defining `const std::uint8_t k_inter_regular_ttf[]`
  (+ its size), added explicitly to `ace_commands`' sources (the `src/commands`
  glob does not see the build-dir file); a header `extern`-declares it. One
  `commands` TU instantiates `stb_truetype` (`#define STB_TRUETYPE_IMPLEMENTATION`)
  and holds the `stbtt_fontinfo`.
  *Rationale:* (i) **The `constexpr` table's quiet virtue was compile-time
  data** — no file I/O, no runtime asset path, nothing for a headless
  `commands`-level job to fail to find, no `FILE*` route around
  `platform::FileSystem` (A3). Embedding preserves it exactly; a runtime font
  path would make caption rendering depend on installed-artifact layout, a new
  failure mode for the offline job and a regression against D-sheet-4. (ii) **A
  generated TU with a `const` array, not a `constexpr` header array**, keeps the
  ~300 KB blob a single definition (one TU pays the compile), mirroring how
  `glyphs.cpp` was single-consumer data — a `constexpr` array in a header would
  bloat every including TU. (iii) **Pure-CMake generation** (`file(READ … HEX)` +
  a `string(REGEX REPLACE …)` into a template, emitted with `file(GENERATE)`/
  `configure_file`) adds no build-time tool dependency; the repo already runs
  Python for `check_levels`, but keeping the embed dependency-free is simpler and
  matches the "no `cmake/` dir, no codegen yet" starting point.
  *Alternative rejected:* **load `Inter-Regular.ttf` from `assets/` at runtime**
  — a `FILE*`/`platform::FileSystem` read on the offline path, a new
  "font-not-found" failure for a headless job, and a dependency on installed
  layout. *Alternative rejected:* a hand-committed C array — 300 KB of literals
  no reviewer can diff and that drifts from the `.ttf`; generate it. **Doc delta:
  A27.**

- **D-truetype_captions-3 — `draw_text` composites 8-bit coverage over the
  caption background in the LINEAR working space, keeping the white+shadow pair.**
  `stb_truetype` rasterizes an 8-bit coverage bitmap per glyph; `draw_text`
  makes two passes (black shadow at `(+scale,+scale)`, then white text), each
  compositing `coverage` over the destination in linear space via
  `arbc::srgb8_to_linear`/`linear_to_srgb8` (`arbc/media/pixel_traits.hpp`),
  re-encoding to sRGB8 — the same transfer `src/render/render.cpp` uses for the
  export background. Transparent backgrounds use the premultiplied-linear `over`
  convention (`render`'s `to_srgb8_over`).
  *Rationale:* (i) **A coverage edge is an alpha blend, not a copy**, so the
  1-bit "opaque write" model (D-sheet-4) cannot represent it; admitting the blend
  is the whole reason the interim table existed. (ii) **The blend must be
  linear** — a gamma-space (sRGB8-byte) blend is the D10 error A20's
  filled-background clause names, wrong in a way a self-generated golden written
  from the same wrong code cannot catch (D-export-5); reusing libarbc's transfer
  guarantees the caption composite matches the rest of the pipeline. (iii) **The
  white+black-shadow pair is kept** — antialiasing makes an arbitrary background
  easier to read against, it does not remove the need to be legible on light,
  dark, mid-grey and transparent backing without analysing it.
  *Alternative rejected:* **sRGB8-byte blend of coverage** — three lines cheaper,
  gamma-wrong, and mid-grey edges are visibly off; the golden would bless the
  error. *Alternative rejected:* **choose black-or-white text by background
  luminance** (D-sheet-4's rejected option) — needs a luminance analysis of the
  strip background, still fails on mid-grey, and has no answer for transparent.
  **Doc delta: A27; A21 clause (2)/(3) amendment.**

- **D-truetype_captions-4 — D-sheet-2's copy-only invariant is NARROWED to the
  tile IMAGE path; text is the admitted composite.**
  The per-tile `std::copy` image composite (`contact_sheet.cpp:359-381`) and the
  background fill stay byte-for-byte copies (`over` degenerates to `replace`,
  tile-rect byte-identity still provable). Only the caption text — drawn *onto*
  the composed sheet at `:384` — composites. A21 clause (2) is amended to say so.
  *Rationale:* (i) **The two surfaces have genuinely different constraints:** a
  tile is an opaque render of a camera at tile resolution, where a copy is exact
  and a blend would be a regression; a caption is antialiased coverage, where a
  copy is impossible. Scoping the invariant by surface keeps the strong,
  testable image law (D-sheet-2) intact where it applies. (ii) **The image law's
  test still passes** — the tile-rect byte-identity sub-assertions
  (`contact_sheet_test.cpp:1507-1522`) are unchanged, which is the reviewer's
  proof the image path did not silently start blending.
  *Alternative rejected:* **retire D-sheet-2 wholesale and composite everything**
  — unnecessary (tiles need no blend) and it discards the byte-identity law that
  catches an accidental future filter on the image path. *Alternative rejected:*
  **rasterize captions into an opaque box then copy the box** — reintroduces a
  hard rectangle around every caption, defeating antialiasing over an arbitrary
  background. **Doc delta: A21 clause (2) amendment.**

- **D-truetype_captions-5 — Retire the whole bitmap table, the fallback box and
  `text_set_bits`; keep `next_code_point`. Missing glyphs are the face's
  `.notdef`.**
  `src/commands/glyphs.cpp`, the `k_glyph_*`/`k_latin1_*`/`k_fallback_glyph`
  constants and externs, `is_mapped`/`glyph_rows`/`for_each_cell`'s run-collapse,
  `text_cells` and `text_set_bits` are deleted. Each decoded code point maps to
  a font glyph via `stbtt_FindGlyphIndex`; index 0 (`.notdef`) is drawn like any
  other glyph, so an uncovered code point renders the face's own box.
  `next_code_point` (the UTF-8 decoder) survives — it is a charset concern
  (D-latin1-1), and malformed input still decodes to U+FFFD, which is uncovered
  and thus `.notdef`.
  *Rationale:* (i) **A face reports its own `.notdef`**, so the editor's
  one-fallback-box-per-run machinery becomes redundant — the missing-glyph box is
  now the font's business, which is the structural end of the hand-drawn charset
  ceiling. (ii) **`text_set_bits` encodes the 1-bit model** (`white ==
  set_bits·scale²`) that antialiasing makes meaningless; keeping it would pin a
  law the new face cannot satisfy. (iii) **The decoder is orthogonal** — UTF-8 →
  code points is needed regardless of how a code point is drawn, and its tests
  (totality, maximal-subpart, code-point-boundary truncation) survive unmodified,
  which is the continuity `caption_latin1` asked for.
  *Alternative rejected:* **keep a one-per-run fallback box in `commands`** (so
  `"中文"` stays one box) — it re-implements, in editor code, degradation the
  face already provides, and the "one box per run" behaviour was a property of a
  *table* with holes, not of a real face; `"中文"` rendering as two `.notdef`
  boxes is the honest face behaviour. **Doc delta: A21 clause (3) amendment.**

- **D-truetype_captions-6 — Font metrics drive `text_width`/`fit_text`; the
  `scale` parameter selects a raster pixel-height; strip geometry is preserved.**
  `text_width` sums the face's scaled horizontal advances (`stbtt_
  GetCodepointHMetrics` at the pixel scale from `stbtt_ScaleForPixelHeight`);
  `fit_text` walks advances (still cutting on a code-point boundary, D-latin1-5,
  still appending the ellipsis on truncation). The public `int scale` now selects
  a target raster pixel-height (a small new constant `× scale`), and
  `caption_scale`/`caption_height = k_glyph_cell_height * caption_scale` are
  **kept** so only glyph shapes — not the sheet's cell layout — change, and the
  goldens re-baseline once.
  *Rationale:* (i) **A real face is proportional** — a fixed `cells ·
  cell_width` width is wrong for it; advances are the face's own measure and are
  what `fit_text` must respect so a fitted caption re-measures consistently
  (the property D-latin1-5 protects). (ii) **Preserving the strip geometry
  bounds the re-baseline** to caption pixels, keeping the arbc_v040 tile
  background stationary and the golden churn minimal (one re-baseline, the
  dependency's whole purpose). (iii) **`stbtt_ScaleForPixelHeight` at a fixed
  height** keeps the raster deterministic and platform-independent (Constraint
  10).
  *Alternative rejected:* **re-flow the whole sheet layout for a proportional
  strip** — larger golden churn for no user-visible gain; the existing
  `8·scale`-px strip comfortably holds Inter at a matching pixel height.
  *Alternative rejected:* **keep integer pixel-replication of a rasterized
  bitmap** — throws away the antialiasing that is the point and reintroduces
  aliasing at scale. **Doc delta: A27.**

- **D-truetype_captions-7 — Doc delta is a NEW `A27` row plus in-place
  amendments to `A20` and `A21`; no `docs/00-design.md` change.**
  A27 records the genuinely new architecture (a second vendored external, a
  build-codegen embed, the first populated `assets/`, linear text compositing in
  L1); A20 and A21 are amended in the house `*(Amended by …)*` form to retire the
  superseded clauses and cross-reference A27.
  *Rationale:* (i) **A new external dependency and a new build seam are
  A-row-worthy facts**, not a clause tweak — this is why `caption_latin1`
  (which only changed A21's charset clause and byte count) correctly used an
  in-place amendment and *this* leaf correctly adds a row: the difference is a new
  structural fact versus a revised number. (ii) **A20's ledger and A21's caption
  clause both make claims this leaf falsifies** ("the embedded glyph table
  stands"; "no `assets/` font, no second external"), so they must be amended in
  place, not left contradicting A27 — the house rule that a superseded claim is
  retired where it lives, with the original text kept as historical record. (iii)
  **`docs/00-design.md` made no font/charset promise**, so there is no D-row to
  amend; general i18n stays open at `:518`.
  *Alternative rejected:* **amend A21 only, no new row** — it would bury a new
  external dependency, a build step and a licence obligation inside a caption
  clause, splitting the bundled-font architecture across a parenthetical instead
  of stating it. *Alternative rejected:* **a new `D<n>` in `docs/00-design.md`**
  — this is structure/build, not UI/UX; the design doc is untouched. **Doc delta:
  A27 + A20/A21 amendments (this decision's own delta).**

- **D-truetype_captions-8 — Ship `OFL.txt` beside the font in-repo; hand the
  artifact-carrying obligation to `editor.packaging.package`.**
  `assets/fonts/OFL.txt` ships with the font binary, establishing the repo's
  first out-of-band licence record (today `stb_image_write.h` carries its text
  inline, which cannot work for a binary `.ttf`, and there is no root/third_party
  `LICENSE`). The vendored set (Inter + `stb_truetype`) is recorded so
  `editor.packaging.package` (`.tji:679-684`) carries the licence text into the
  installed artifact.
  *Rationale:* (i) **A bundled font whose licence text does not travel with it
  is the actual legal exposure**, and it is created at *packaging* time, not
  vendoring time — so the in-repo `OFL.txt` is this leaf's job and the
  artifact-staging is `package`'s (already in its scope: *"embedding
  fonts/icons"*). (ii) **This is not a new WBS task** — `package` exists; this
  leaf only records the obligation and files the licence text where `package`
  will find it. The cross-task note is surfaced in the return summary so
  `package`'s refinement honours it.
  *Alternative rejected:* **inline the OFL text in a header comment** like
  `stb_image_write.h` — impossible for a binary `.ttf` and it would not travel
  into a binary artifact anyway. *Alternative rejected:* **register a new
  "bundle licence into artifact" leaf** — duplicates `package`'s existing charter.
  **No doc delta beyond A27's licence-record clause.**
